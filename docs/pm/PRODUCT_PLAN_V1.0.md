- PROJECT_PHASE：**PLAN**
- Product Goal：朋友突然邀请打麻将时，用户能**快速选定具体地方玩法**，用**真实麻将牌面**看懂最关键的上桌规则——「能不能胡、为什么、差什么」以及各类例外。
- Target Users：①完全不会打麻将的新手；②玩过两三次、规则记不清的半新手；③临时被拉去打**自己不熟悉地区**麻将（海南/四川/重庆/广东）的人。
- Problem：网上规则互相矛盾、真假难辨；熟人解释太专业听不懂；「眼」与「花」的关系最容易误解；纯文字规则无法直接对照手牌。
- Core Value：**牌面先行，一句人话解释，明确玩法与判断前提**。本产品不是线上打麻将、不是考试、不是计分/算钱工具。

## User Flow（UX 真源；每条写清入口／主要动作／可见结果，可逐条验收）

- **UF-01｜按地区查具体玩法**。入口：首页「地区」大入口。主要动作：选地区（海南/四川/重庆/广东）→ 选该地区下**具体玩法名字**（如「海南有番参考玩法」「四川血战到底参考」「广东推倒胡·波克版本」「重庆血战参考」）→ 看规则简介 → 翻看对照牌面 → 进入「3分钟速看」。可见结果：进入的是**具名玩法**而非省级泛称；页面显示版本名、来源、核实等级；3分钟速看上无登录/考试门槛。
- **UF-02｜按问题查术语**。入口：首页「问题」大入口。主要动作：选「什么是眼」等术语问题 → 看有眼/无眼**真实牌面对照** → 读一句白话原因 → 返回。可见结果：每个术语页至少一句白话解释＋真实牌面图；返回不丢所在查询。
- **UF-03｜问「为什么不能胡」**。入口：首页「问题」列表项「为什么不能胡」；或由玩法详情/术语详情的对照牌面追问进入。主要动作：**从 V1 已审核示例列表中选择一个牌例**（列表项＝示例标题＋一句话预览，如「13张等待另一张二条」「四川：有三种花色，结构完整仍不能胡」）→ 系统区分 13 张（等待）与 14 张（不完整），并按「手牌结构」与「地域条件」两级判定 → 说明缺哪张牌或缺哪项资格。可见结果：给出「能胡／不能胡／未满足额外条件／依据不足」四态结论与理由，绝不对 14 张不合法结构说「再摸一张就胡」。**牌例来源边界（B-02）**：V1 **只从已审核示例 E01～E16 中选取**（对应 `examples/visual-examples.json`）；**不提供手工录牌、任意牌张输入或动态判牌**。此处「输入」**仅指按示例 ID / 标题关键词搜索**（与 UF-02 / S10 搜索契约一致，`FR-11`），不是自由录牌。未选牌例时显示空态「请从上方示例列表选择一个牌例」；无匹配搜索项时显示「未找到匹配示例」。选例入口在 S5/S7；验收见 AC-52。
- **UF-04｜海南：区分「二五八眼」与「对应座位花」**。入口：海南玩法详情。主要动作：看「二五八做眼」示例与「对应座位花」示例。可见结果：**花牌另放、不与眼合并**展示；明示「花牌不取代对子当眼」；春花必须标座位风，非 258 眼只能按给定前提解释。
- **UF-05｜四川：定缺与变体开关**。入口：四川玩法详情。主要动作：看「结构看似完整但有三门花色」的示例 → 高亮**违背定缺**的花色；变体项（如换三张）以开关/版本属性呈现。可见结果：明确「定缺」是该玩法闸门；换三张显示为「按具体玩法版本」而非必有。
- **UF-06｜广东推倒胡：来源不同结果不同**。入口：广东玩法详情。主要动作：看同一完整结构、最后一张来源不同（自摸 / 普通点炮）的两个示例。可见结果：只有自摸/抢杠胡显示可胡；普通点炮明确显示**不胡**；标注这是**波克发行版本**、不代表全广东。
- **UF-07｜对比两个规则版本**（**非核心 P1 扩展分支**，对应 FR-10；验收 AC-20，维持**非关键**）。入口：具体玩法详情内的「对比」入口。主要动作：选择第二个明确规则版本 → 查看差异与**证据等级**。可见结果：差异逐项列出并标注来源；证据不足处明确展示占位原因而非编造。**对账说明（B-01）**：UF-07 不再是孤儿——正式 AC 行 AC-20 已显式关联本 UF；本 UF 属非核心 P1 扩展，其验收标准 AC-20 保持**非关键**（不得一边称其为关键任务、一边无验收）。
- **UF-08｜设置主题与语言**。入口：右上角「设置」。主要动作：选浅色/深色/跟随系统 ＋ 简体中文/English/跟随系统 → 返回。可见结果：设置即时生效、跨页一致；**返回后仍保持用户所在规则页与浏览状态**；重启后设置保留。

## Out of Scope（明确不做；以交接包 §5「明确不做」为准）

- 麻将**线上对战**（含联机房间）。
- **AI / 拍照自动判牌**（本产品为静态教学示例，不做实时图像识别判牌）。
- **手工录牌 / 任意牌张输入 / 动态或实时判牌**（B-02）：V1 的牌例判定**只从已审核示例 E01~E16 中选取**；用户侧「输入」仅指按示例 ID/标题搜索，**不建立自由录牌或自动裁定引擎**。
- **复杂算番 / 算钱**（不做各家分值、赔付、底分计算）。
- **赌注 / 下注**及一切博彩功能；本产品**非博彩产品**，不做金额计算。
- **积分排行榜**。
- **练习题 / 考试 / 小测验**。
- **大型麻将历史百科**。
- **强制启动引导页**（仅用系统 SplashScreen，尽快进入首页，不强制停留）。
- 不把「通用牌型结构」等同某地区可胡；不把花牌当对子。

## Technical Approach

- **Android 原生优先**：Kotlin + Jetpack Compose + Material 3 + Android 官方字符串资源。MagicPath 的 **React 原型不是现成 Compose APK**，仅作**交互与视觉真源**；Android Builder 需按本计划与 `DESIGN_FREEZE` 在 Compose 中重新实现。
- **内容边界＝固定静态教学（B-02，硬约束）**：V1 的全部「牌例判定」**只从已审核示例 E01～E16 中选取**（`examples/visual-examples.json`）。**不提供手工录牌、任意牌张输入、拍照识别或任何动态/实时判牌能力**。用户侧「输入」**仅指按示例 ID / 标题搜索**（FR-11，与 S10 搜索契约一致）。系统不做自动裁定引擎，只做「两级解释」（手牌结构级＋地域条件级）；本边界写入 Out of Scope 与 AC-52。
- **规则数据＝静态离线 JSON**：以 `rules/rule-profiles.json`（5 份具名档案）与 `examples/visual-examples.json`（E01~E16）为 **Phase1 输入资产**；Builder 可在**保持语义与 ID 稳定**前提下正规化（不删 ID、不改牌张 ID、不改 status 语义）。数据随 APP 打包，离线可用。
- **不引入线上对战或牌局 API**；来源链接仅在联网时可点，不影响离线可用性。
- **牌图**：使用本包 `tiles/png/`（42 种，W1-W9/P1-P9/S1-S9/Z1-Z7/F1-F8）PNG；必要时制作自有扩展资源；**避免授权不明第三方图库**。
- **主题/多语言**：复用 Android 官方/成熟组件（Material 3 主题、官方字符串资源）；不改自研基础引擎；启动画面用系统 SplashScreen API，合入正式工程主题（不覆盖现有主题文件）。

## Risks

- **R-1 桌规不可穷尽**：海南各市县/朋友自定义桌规无法通过网络穷尽。对策：不支持确定胡牌判定，走「先问桌规」路径（E07 `next_condition=ASK_TABLE_RULE`），并允许收藏「上桌前要问的三件事」。
- **R-2 低置信玩法误用**：重庆档案为 C 级，存在多种开关。对策：`LOW_CONFIDENCE_VARIANT_OPTIONS` 灰态，争议条款不出确定结论（E15 `VARIANT_NOT_FIXED`）。
- **R-3 未证实术语被当真**：「当花又当眼」无可靠原文。对策：`TERM_UNVERIFIED`，呈现「该说法暂无法核实」，绝不编造定义或让用户解释（AC-27/AC-25）。
- **R-4 误判风险**：把省级泛称当统一规则、把通用结构当某地区可胡、把花牌当眼。对策：具名档案＋证据等级＋COMMON 语义明示＋四态结论（AC-06/AC-26/AC-27）。
- **R-5 商标/商店重名未做法定检索**：名称仅做普通公开搜索，**未完成法定商标检索或 Google Play 同名保证**；上线法律/商店审核以实际上架要求为准。对策：不宣称商标检索通过；上架前按商店政策核查（**不新增 Human Gate**）。
- **R-6 图标安全区**：`p046_adaptive_fg.xml` 金色光芒笔画最远点约 38.5dp > 33dp 安全区（66dp/2），圆形遮罩下可能裁切。对策：AC-28 真机录屏必验；如影响辨识，缩放前景矢量（不动品牌色与构图）。
