- Plan Version：**PRODUCT_PLAN V1.1**（需求真源；承 V1.0，Phase2 开发基线）
- PROJECT_PHASE：**DEVELOP**
- Product Goal：朋友突然邀请打麻将时，用户能**快速看懂海南麻将最关键的上桌规则**，用**真实麻将牌面**看懂「能不能胡、为什么、差什么」以及各类例外。
- Target Users：①完全不会打麻将的新手；②玩过两三次、规则记不清的半新手；③临时被拉去打**海南麻将**、看不懂地方规矩的人。
- Problem：网上规则互相矛盾、真假难辨；熟人解释太专业听不懂；「眼」与「花」的关系最容易误解；纯文字规则无法直接对照手牌。
- Core Value：**牌面先行，一句人话解释，明确玩法与判断前提**。本产品不是线上打麻将、不是考试、不是计分/算钱工具。

## User Flow（UX 真源；每条写清入口／主要动作／可见结果，可逐条验收）

- **UF-01｜查海南玩法**（【V1.1 改写】：原「按地区查具体玩法」多地区版已删除，地区 5→1）。入口：首页「问题」下的玩法相关入口（**首页不再有「地区」大入口**；【V1.1】海南只有唯一具名玩法 `HN_FAN_REFERENCE`）。主要动作：进入海南玩法详情 → 看规则简介 → 翻看对照牌面（E04~E07）→ 进入「3分钟速看」。可见结果：进入的是**具名玩法**（海南「有番」参考玩法）而非省级泛称；页面显示版本名、来源、核实等级；3分钟速看上无登录/考试门槛。
- **UF-02｜按问题查术语**。入口：首页「常见问题」大入口。主要动作：选「什么是眼」等术语问题 → 看有眼/无眼**真实牌面对照** → 读一句白话原因 → 返回。可见结果：每个术语页至少一句白话解释＋真实牌面图；返回不丢所在查询。
- **UF-03｜问「为什么不能胡」**。入口：首页常见问题列表项「为什么不能胡」；或由玩法详情/术语详情的对照牌面追问进入。主要动作：**从已审核示例列表中选择一个牌例**（列表项＝示例标题＋一句话预览）→ 系统区分 13 张（等待）与 14 张（不完整），并按「手牌结构」与「（海南）玩法条件」两级判定 → 说明缺哪张牌或缺哪项资格。可见结果：给出「能胡／不能胡／未满足额外条件／依据不足」四态结论与理由，绝不对 14 张不合法结构说「再摸一张就胡」。**牌例来源边界（B-02）**：V1 **只从已审核示例 E01~E07、E16（共 8 例）中选取**（对应 `examples/visual-examples.json`，【V1.1】原 E08~E15 已随多地区删除）；**不提供手工录牌、任意牌张输入或动态判牌**。此处「输入」**仅指按示例 ID / 标题关键词搜索**（与 UF-02 / S10 搜索契约一致，`FR-11`），不是自由录牌。未选牌例时显示空态「请从上方示例列表选择一个牌例」；无匹配搜索项时显示「未找到匹配示例」。选例入口在 S5/S7；验收见 AC-52。
- **UF-04｜海南：区分「二五八眼」与「对应座位花」**。入口：海南玩法详情。主要动作：看「二五八做眼」示例与「对应座位花」示例。可见结果：**花牌另放、不与眼合并**展示；明示「花牌不取代对子当眼」；春花必须标座位风，非 258 眼只能按给定前提解释。
- **UF-05｜【V1.1 已删除】**（原「四川：定缺与变体开关」）。删除依据：用户指令「其他所有地区的全部取消，只留海南的」「所有结构上的地区全部取消」；对应 FR-10 相关变体对比一并删除。原四川判例 E08~E10 已移除，`AC-26` 四川条目同步删除。
- **UF-06｜【V1.1 已删除】**（原「广东推倒胡：来源不同结果不同」）。删除依据同上；原广东判例 E11/E12 已移除，`AC-44` 广东来源条目同步删除。
- **UF-07｜【V1.1 已删除】**（原「对比两个规则版本」，非核心 P1）。删除依据：海南单地区仅存唯一玩法档，无第二版本可对比；地区/版本对比入口已从前端移除。对应 FR-10、AC-20、S8 规则对比屏同步删除。
- **UF-08｜设置主题与语言**。入口：右上角「设置」。主要动作：选浅色/深色/跟随系统 ＋ 简体中文/English/跟随系统 → 返回。可见结果：设置即时生效、跨页一致；**返回后仍保持用户所在规则页与浏览状态**；重启后设置保留。

## Out of Scope（明确不做；以交接包 §5「明确不做」为准）

- 麻将**线上对战**（含联机房间）。
- **AI / 拍照自动判牌**（本产品为静态教学示例，不做实时图像识别判牌）。
- **手工录牌 / 任意牌张输入 / 动态或实时判牌**（B-02）：V1 的牌例判定**只从已审核示例 E01~E07、E16（共 8 例，【V1.1】原 E08~E15 随多地区删除）中选取**；用户侧「输入」仅指按示例 ID/标题搜索，**不建立自由录牌或自动裁定引擎**。
- **复杂算番 / 算钱**（不做各家分值、赔付、底分计算）。
- **赌注 / 下注**及一切博彩功能；本产品**非博彩产品**，不做金额计算。
- **积分排行榜**。
- **练习题 / 考试 / 小测验**。
- **大型麻将历史百科**。
- **强制启动引导页**（仅用系统 SplashScreen，尽快进入首页，不强制停留）。
- 不把「通用牌型结构」等同某地区可胡；不把花牌当对子。

## APP 基础能力声明（面向用户的 APP 必填，照 `docs/sop/app-theme-i18n.md` 全局默认自动继承）

- 适用性：**是**——本项目面向用户交付 **HTML/PWA** 应用（有用户界面）。【V1.1】原 Android APP 形态已改为 HTML/PWA。
- 平台与技术栈：**HTML/CSS/原生 JS 静态站点 ＋ PWA**（【V1.1】原 Kotlin / Jetpack Compose / Material 3 / Gradle / Android 字符串资源**全部取消**）；复用已验收 `prototype/` 的原生 CSS 语义 Token（自定义属性）与 `i18n.js` 字典方案；运行时依赖由既有 Reuse Audit 按既定顺序确认。

- 设置持久化：重启保留；切换主题/语言**不丢业务状态、进度与当前操作**。

- 语音能力：**否**——本 APP 不是语音类 APP；不涉及语音指令/发音/语速本地化。对应模板语音 AC 记为不适用（见 AC-36）。
- 技术栈复用判定（先查项目已有依赖；本项目为已验收 HTML 原型，其主题/i18n 基础设施可复用，故优先候选来自标准 Web 能力）：

## Technical Approach

- **【V1.1 技术路线】HTML/PWA 静态站点**：最终形态为 HTML/CSS/原生 JS ＋ PWA（`prototype/`）。**取消 Android 原生（Kotlin + Jetpack Compose + Material 3 + Gradle + APK + 应用商店）全部任务**；原「Android Builder 在 Compose 中重新实现」作废。唯一视觉与交互真源＝用户 2026-10-09 验收通过的 `prototype/`。
- **PWA 工程化（V1.1 新增）**：`prototype/manifest.webmanifest`（name/short_name/start_url/scope/display/theme_color/background_color/lang/dir/icons）；`prototype/sw.js` Service Worker（版本常量 `SW_VERSION`、install 预缓存全部同源资源＋skipWaiting、activate 清旧缓存＋clients.claim、fetch 导航 network-first / 静态 cache-first、仅同源 GET）；`app.js` 在 boot 注册 SW 并带 `http(s)` 协议守卫（`file://` 双击打开不受影响）；`registration.onupdatefound` ＋ `controllerchange` 触发站内 `.notice` 更新提示。
- **内容边界＝固定静态教学（B-02，硬约束）**：V1 的全部「牌例判定」**只从已审核示例 E01~E07、E16（共 8 例）中选取**（`examples/visual-examples.json`，【V1.1】原 E08~E15 已删除）。**不提供手工录牌、任意牌张输入、拍照识别或任何动态/实时判牌能力**。用户侧「输入」**仅指按示例 ID / 标题搜索**（FR-11，与 S10 搜索契约一致）。系统不做自动裁定引擎，只做「两级解释」（手牌结构级＋玩法条件级）；本边界写入 Out of Scope 与 AC-52。
- **规则数据＝静态离线 JSON**：以 `rules/rule-profiles.json`（【V1.1】现仅保留 **1 份**海南具名档案 `HN_FAN_REFERENCE`，原 5 份随多地区删除）与 `examples/visual-examples.json`（E01~E07、E16）为基础；已在 `prototype/data/*.js`／`*.json` 双份等价落盘。Builder 可在**保持语义与 ID 稳定**前提下正规化（不删 ID、不改牌张 ID、不改 status 语义）。数据随 PWA 打包，离线可用。
- **不引入线上对战或牌局 API**；来源链接仅在联网时可点，不影响离线可用性。
- **牌图**：使用本包 `tiles/png/`（42 种，W1-W9/P1-P9/S1-S9/Z1-Z7/F1-F8）PNG；必要时制作自有扩展资源；**避免授权不明第三方图库**。
- **主题/多语言**：复用已验收 `prototype/app.css` 的语义 Token（CSS 自定义属性）与 `prototype/i18n.js` 字典；不自研基础引擎；启动页为 HTML 模拟，合入主题三态。
- **正式原型证据归档（B-07）**：C 方案可点击原型已由编排者归档到 **`docs/pm/evidence/prototype/`**（`README.md` ＋ 首页/海南地区页/设置页 3 份 PDF 快照，含 SHA-256 与实测观察）。原型身份：MagicPath `https://designs.magicpath.ai/v1/smooth-field-4409`，revision=`459123263147245568`（project=`458973763359367168`、component=`458974093736292352`）。**证据分级（三者必须分开记）**：

## Risks

- **R-1 桌规不可穷尽**：海南各市县/朋友自定义桌规无法通过网络穷尽。对策：不支持确定胡牌判定，走「先问桌规」路径（E07 `next_condition=ASK_TABLE_RULE`），并允许收藏「上桌前要问的三件事」。
- **R-2【V1.1 已删除】**：原「重庆低置信玩法误用」风险随重庆地区取消而移除（对应 E15 已删除）。
- **R-3 未证实术语被当真**：「当花又当眼」无可靠原文。对策：`TERM_UNVERIFIED`，呈现「该说法暂无法核实」，绝不编造定义或让用户解释（AC-27/AC-25）。
- **R-4 误判风险**：把通用结构当海南可胡、把花牌当眼。对策：具名海南档案＋证据等级＋COMMON 语义明示＋四态结论（AC-06/AC-27）。
- **R-5 商标/应用名重名未做法定检索**：名称仅做普通公开搜索，**未完成法定商标检索或应用市场同名保证**；上线法律/审核以实际要求为准。对策：不宣称商标检索通过；上架前核查（**不新增 Human Gate**）。
- **R-6【V1.1 已改写】PWA 图标安全区**：原 Android adaptive icon 安全区问题随路线取消；现图标由 `play-store-512.png` 派生（192/512 maskable/180/32）并已逐尺寸校验，maskable 裁剪为观察项（AC-28）。
- **R-7 牌图放大清晰度**：PNG 192×272px，大倍率放大发虚。对策：UI 限制放大倍数（≤约 1.8×）或后续补高清素材；非阻塞。
- **R-8【V1.1 已缩范围】来源同源**：海南（R-HN-CROSS 转载属性）存在同源可能，对策：**海南仅维持 B 级**（转载同源风险）；原广东（波克/JJ 同源）条目随地区取消。
- **R-9 主题/语言回归**：切换主题/语言若重置页面状态会造成体验断裂。对策：AC-16/AC-33「切换不丢状态」＋跨页一致性 AC-11/AC-29。
